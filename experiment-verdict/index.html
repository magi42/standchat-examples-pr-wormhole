How it works

A decision room, with a real conversation.

The evidence is a deterministic local simulation. The discussion uses Stand’s visitor API and a custom inline interface. There are no scripted AI replies.

Try it

  1. Choose ship, stop, or investigate and set your working assumption.
  2. Open the evidence in order: segments, a synthetic event trail, then sample-size caveats. Use the replay’s buttons to play, pause, or inspect any event.
  3. Choose “Discuss my decision,” type your reasoning or a question, and send. The visible context quote travels with it. You can remove the quote before sending.
  4. Revise your choice to attach an updated snapshot to your next message. “Now, about your product” prepares a new topic in the same thread. Resetting the evidence keeps the live conversation and your draft.

Copy this example

npx degit standchat/examples/experiment-verdict my-decision-room

Serve the copied folder with any static HTTP server. Keep app.js, scenario.js, style.css, mark.svg, stand-inline.js, and stand-visitor.js beside index.html. No install or build step is needed. Remove the two /_shared/ references and <sx-example-bar> when using it on your own site.

Replace the Stand script with your installation snippet from Sites in Stand and set the element’s site attribute to that same Site ID. demo uses Stand’s shared demo responder, not a Signalburrow team or your account’s history.

The integration

<script defer src="https://cdn.stand.chat/widget/stand.js"
  data-stand-id="demo"></script>
<script type="module" src="./stand-inline.js"></script>
<stand-inline site="demo" scope="my-experiment" look="card"
  grow="unfold"></stand-inline>
// This prepares context. It does not send a message.
chat.quote = contextSnapshot({ decision, stage, priority });
chat.setAttribute('prompt', 'Discuss tradeoffs; sample data is fictional.');
// The visitor writes and sends from the inline composer.
// First send: POST /v1/sessions { initialMessage, prompt, ... }
// Later sends: POST /v1/sessions/:id/messages
// Replies arrive over WebSocket and reconcile with HTTP reads.

prompt is session context, limited to 2,000 characters; it is not secret or an authorization boundary. Evidence updates use the visible quote, included only on the visitor’s next send. Replies are safely rendered and cannot control the page. The copied client preserves responder identity, notices, attribution, handoffs, follow-up offers, session recovery, and message IDs for safe retries.

Read the official custom chat UI contract (beta). The chart counts and interval assumptions live in scenario.js; run node --test experiment-verdict/scenario.test.mjs from this repository to verify the arithmetic.
