Room for your kind of business
Good commerce makes
space for the exceptions.
Most orders follow a line. The memorable ones branch out. Shopgrove is an imagined commerce platform built around a simple idea: understand the edge cases before you commit to the system.


Built in
A solid starting point.
Mixed availability and quantity-based wholesale pricing follow explicit rules in this demo. Buyer approval, payment terms, returns, and stock synchronization are outside this catalog.
Add-on
Make it your own.
Personalization adds a per-item fee and production time. An actual implementation would need an extension and decisions about proofs, edits, and order cutoffs.
Expert review
Know where to go deeper.
Multiple destinations can be modeled here. Address validation, tax jurisdictions, routing, and fulfillment partners need a separate fit review. No compatibility is promised.


How it works
A useful preview. An informed conversation.
Try a sample scenario or add exceptions, move through the three stages, then send a question. The order model runs locally in integer cents. Stand handles the real conversation in the page through its custom chat UI contract (beta).
1. Copy the complete folder
npx degit standchat/examples/unusual-order my-shopgrove
Serve it as static files. There is no install or build step. Keep index.html, style.css, app.js, order-model.js, product.svg, product-personal.svg, stand-inline.js, and stand-visitor.js together. The optional /_shared/ files only add the example bar.
2. Connect your own Stand site
Replace site="demo" on the inline element and data-stand-id="demo" on the retained installation script with your public Site ID from Sites in Stand. The launcher is hidden using initiallyHideChatButton(). The copied inline client handles this conversation independently.
3. Send a visitor-approved snapshot
import { contextMessage } from './order-model.js';

// In the visitor's submit handler:
const sent = await chat.ask(
  contextMessage(order, question.value)
);
The first message creates a session. A bounded prompt describes the fictional catalog; the visible message carries the question, selected items, stage, quantities, totals, and assumptions. Later submissions include a fresh snapshot. Opening the discussion or changing an exception never sends a message.
4. Preserve the conversation contract
The local client supports responder discovery, AI/human disclosure, HTTP sends, WebSocket replies, reload recovery, reconnects, safe message rendering, handoff cards, email follow-up, notices, and attribution. Failed sends retain their message ID; uncertain session creation needs a visitor decision. Quotas and entitlements apply.
The demo Site ID reaches Stand’s shared demo, not a Shopgrove team or your account. No inventory, payments, shipping services, or automatic page mutations are connected. View source ↗
