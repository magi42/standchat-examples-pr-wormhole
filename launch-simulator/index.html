THE FINE PRINT, IN PLAIN SIGHT
A model you can
take apart.
This is a teaching tool, not a capacity test or a hosting offer. No infrastructure is provisioned and no bill is charged.

What does one hour mean?
The chosen base request rate lasts exactly 3,600 seconds. A bot spike adds twice that rate, with the same request mix. There is no burst curve or bot detection. Every admitted response transfers its profile’s assumed size, including cache hits.
What work does each app do?

Caching hits 80% of cacheable requests; the rest reach origin. AI-heavy makes every origin request an AI call at three times the normal invented rate. It does not change the CPU or database assumptions.
Where does the bill come from?
All rates are fictional USD: $2/hour base, $0.08 per million incoming requests, $0.024 per CPU core-minute, $0.12 per million database operations, $0.06 per decimal GB transferred, and $0.002 per AI call ($0.006 in AI-heavy mode). One GB is 1,000,000 KB.
CPU core-minutes = origin requests/second × CPU milliseconds/1,000 × 60. Other usage totals multiply the per-second rate by 3,600. Only display values are rounded; rounded line items can differ from the total by a cent.
What do capacity and spending limits mean?
Resource percentages divide required work by 8 CPU cores or 12,000 database operations/second. Values above 100% flag a mismatch, not a prediction of latency or failure. No automatic scaling, retries, queues, or resource-based dropping are modeled.
A guardrail proportionally admits requests before caching and origin work. The admitted fraction is (budget − base − ingress) ÷ uncapped variable cost, clamped to 0–100%. Deferred requests do no further work. Base and ingress always accrue, so an unusually low budget can still be exceeded. This is a local model, not a real enforcement guarantee.


    
BUILD SOMETHING LIKE THIS
How it works
The simulator runs in your browser. Stand Chat carries the conversation, with the selected scenario attached.
1. Try the full loop
Choose an app, move the traffic slider, then try the bot or AI preset. Toggle caching or a spending limit. Click a cost or resource to review its frozen scenario. Write a question and press Send to start a real Stand conversation.
Native controls work with touch and keyboard. Use arrow keys on the traffic slider. Pause the diagram or use your system’s reduced-motion setting.
2. Copy the folder
npx degit standchat/examples/launch-simulator my-launch-simulator
Serve it over HTTP with any static server. No installation or build is needed. Keep index.html, style.css, app.js, model.js, stand-inline.js, and stand-visitor.js together. The repository’s /_shared/ files only add example chrome; remove those two head references in your own copy.
3. Connect your site
// app.js — use your registered Site ID
const SITE_ID = 'demo';
const chat = document.createElement('stand-inline');
chat.setAttribute('site', SITE_ID);
chat.setAttribute('scope', 'launchmere-v1');
chat.setAttribute('grow', 'unfold');
Replace demo in app.js and the Stand script’s data-stand-id with your Site ID from Sites in Stand. Register your actual domain and configure your responders. The shared demo uses Stand Chat’s demo AI and does not write to your account.
4. Send context on purpose
const snapshot = calculate(state);
const context = scenarioContext(snapshot, selectedItem);
chat.setAttribute('prompt', context); // first-session context
chat.quote = context; // attached to the next visitor message
// The visitor reviews the snapshot, writes, and chooses Send.
The copied inline element raises its quote limit to 2,000 characters for this complete snapshot. The prompt uses Stand’s supported session context; quotes travel as ordinary message text, including when the visitor selects a new scenario mid-conversation. Follow-up messages stay unmodified.
The local client preserves notices, attribution, AI/human identity, handoff cards, email follow-up offers, safe message rendering, reconnects, and explicit retry decisions. Session recovery uses this tab’s session storage when available. No responder text executes as code or edits the simulator. See the official custom chat UI contract (beta).
