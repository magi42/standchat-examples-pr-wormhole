          Hookline is a fictional company. This page demonstrates a custom chat UI on Stand Chat’s Visitor API.

          How it works

          Turn zero-result searches into conversations

          “Does it work with our ERP?” is the question people ask most about a product that lives in their stack, and a “No results” page is where many of them leave. Here the app directory’s search box never dead-ends. When nothing matches, or the query reads like a question, the same box becomes a conversation on Stand’s Visitor API, and the search and the visitor’s stack go along with it.

          There’s no stand.js on this page. The box, the results, the conversation and the flow cards are plain JavaScript in this folder, with no dependencies.

          Try it

          1. On your first visit, the search box types Acme ERP, an app the directory doesn’t have, and the results turn into “No Acme ERP yet”: who answers, and what your question would carry. It’s an example; nothing is sent.
          2. Search for the tools you really use. Every app here is invented, so yours won’t match, which is the point. Add a couple of the directory’s apps to your stack on the way.
          3. Ask. The answer arrives right under the box, and the apps and flows it mentions come as cards: Add to stack on an app, Try this flow on a flow, which opens its steps and runs a test.
          4. Open an app’s card and use Missing a trigger or action? Ask, or type a question like how do I add a filter? and press Enter.
          5. Reload mid-conversation: everything comes back where it was. End conversation closes it for good.
          Conversations here use Stand Chat’s shared demo site, which answers on any domain through Stand Chat’s demo Stand-in. It follows this page’s prompt, so it answers as Hookline, but Hookline is made up. With your own Site ID, your own Stand-ins and team answer.

          1. Search first, ask when search runs out

          The directory search is local and instant: 106 invented apps, matched on names, keywords, categories, and trigger and action names, with typo tolerance for names only. Two things turn a search into a question. A query can read like one, and then “Ask: …” becomes the top result. Or a query can match nothing and sit still for 450 milliseconds, so a half-typed name never flashes a question at you.

          export function isQuestion(query) {
  const text = String(query).trim();
  if (/\?\s*$/.test(text)) return true;
  const words = normalize(text).split(' ').filter(Boolean);
  // "can I sync…", "how do I…", "is there…"
  if (words.length >= 3 && QUESTION_START.test(words.join(' '))) return true;
  return words.length >= 6; // a sentence, not an app name
}

          2. The same box becomes the conversation

          The results area has five views: idle, results, the “no match” starter, an app’s card, and the conversation. They share one container that animates its height between them, and the input never moves: it’s the search field, the question field and, once a conversation starts, the reply field. The newest exchange sits right under it, like the top search result, with earlier ones folded below.

          function currentView() {
  if (appId) return 'app';
  if (inChat()) return 'chat'; // a conversation is going: the box is its composer
  if (ask) return 'starter'; // about an app, a flow, or a search that found nothing
  const q = query.trim();
  if (!q) return 'idle';
  // A question: "Ask: …" on top, then any apps it names.
  if (isQuestion(q)) return mentionedApps(q).length ? 'results' : 'starter';
  const result = search(q); // the whole directory, whatever the filter
  if (!result.good && settled) return 'starter'; // "No Acme ERP yet"
  return 'results';
}

          The magnifier in the box turns into a speech bubble whenever Enter will send to the team rather than open an app, and the button next to it says Ask or Send. Nothing is created until one of them is pressed.

          3. Context rides along with each message

          Each message starts with a short context prefix: what was searched, whether it matched, the closest apps, the app or flow it’s about, and the visitor’s stack when it changed. The team reads it in Stand, the AI Stand-in uses it, and this page parses it back into the chips under each question, so a reload restores them from the transcript itself. Here is what your next question would carry right now:

          Your next message

// '(searching “Acme ERP” · no match · stack: Formlane, Pipewell) '

// Only known segments count, so a visitor's own brackets stay put:
parsePrefix('(just curious) Does it work?'); // { context: null, … }

          4. The prompt

          The first message starts the conversation with a private prompt: who Hookline is, the facts visitors ask about, how the prefix works, and the names replies may point at. It’s the same for everyone and stays under Stand’s 2,000-character limit (this one is 1,995 characters); what each visitor searched travels in the messages instead.

          5. Replies hand over working pieces

          The prompt asks the Stand-in to name apps and flows in double square brackets, from a closed list. The page turns a known name into a chip in the text and a card under the reply: an app gets Add to stack, a flow gets Try this flow, which opens its steps right there. An unknown name stays plain text, and a reference only ever opens or highlights something on this page. The “Caught webhook → Create record” flow takes its target app from the conversation, so an answer about Pipewell opens a flow into Pipewell.

          const REF = /\[\[\s*(?:(app|flow)\s*:\s*)?([^[\]\n]{1,100}?)\s*\]\]/gi;

// "Pipewell", "App: Pipewell" and "app:pipewell." all find Pipewell.
// "->" counts as "→". No match returns null, and the name stays plain text.
export function lookup(kind, name) {
  const k = key(name);
  const type = kind?.toLowerCase();
  const app = type !== 'flow' && APP_NAMES.get(k);
  const flow = type !== 'app' && FLOW_NAMES.get(k);
  return app ? { kind: 'app', app } : flow ? { kind: 'flow', flow } : null;
}

          6. What the team learns

          A conversation that starts here opens, in Stand, with the reason it started: the search that failed, the app that was missing something, or the flow in question, plus the visitor’s stack. The prompt also asks the Stand-in what a missing app should connect to, so the transcript holds the integration and the use case side by side. Read a week of these and you have next quarter’s integration list, in your visitors’ own words. First messages look like this:

          (searching “Acme ERP” · no match · closest: Ledgerly · stack: Formlane, Pipewell) Can I sync invoices from Acme ERP into Pipewell as deals?

(app: Formlane · triggers: New form entry, New partial entry, New payment entry · actions: Create prefilled link, Find entry · missing trigger or action) Can it trigger when someone abandons a form halfway?

(flow: Caught webhook → Create record · steps: Catch hook in Webhooks → Create contact in Pipewell · stack: Webhooks) Can I only let paid invoices through?

          The files

          • stand-visitor.js is the network client, the same one as in Stand Inline, with its own storage keys. No DOM.
          • conversation.js is the conversation model: the context prefix, exchanges, references and safe formatting. No DOM, no network.
          • omnibox.js is the box: search results, the starter, app cards and the conversation.
          • search.js, catalog.js and icons.js are the directory: ranking, the invented apps and flows, and their icons, drawn from data.
          • flows.js is the flow editor: step cards, the “+” between them and the test run.
          • prompt.js is the prompt, built from the catalog so its names always match the page. stack.js keeps the visitor’s stack in sessionStorage, dom.js is a template tag that escapes everything it isn’t told is safe, and site.js wires up the rest of the page.

          Good to know

          • Honest about AI. The box says who answers, as Stand names them, and whether it’s AI or a person. The badge changes when someone from the team joins.
          • Closing isn’t ending. Searching again or opening an app keeps the conversation going. Only End conversation ends it in Stand.
          • Nothing starts by accident. Typing, opening an app or the example search never creates a conversation. Only pressing Ask or Enter on a question does.
          • A reload keeps everything. The transcript comes back from Stand, the chips from the messages’ prefixes, and the stack and an unsent question from sessionStorage.
          • Nobody around? Search keeps working, and the Ask button explains that nobody can answer right now, with a way to check again.
          • Keyboard and screen readers. The box is a combobox: arrows move through results, Enter opens or asks, Escape clears, and / or ⌘K jumps to it. New replies are read out whole. With reduced motion, the box doesn’t animate and the example appears at once.
          • It’s a beta contract. The Visitor API can gain fields and events; the client ignores what it doesn’t know.

          This example’s brief

          An app-automation platform with a huge app directory. “Does it integrate with X?” is its most-asked question, and “No results” is where those visitors leave. Make the directory’s search box never dead-end: when nothing matches, or the query reads like a question, the results area morphs into a conversation with the search and the visitor’s stack attached. Offer “Ask: …” as the top result for questions, and “Missing a trigger or action? Ask” on every app card. Let replies point at apps and flow templates by name, and render them as cards you can add to your stack or try in a mini flow editor. One conversation, with a compact context prefix on each message. Warm off-white, orange, bold type, step cards.

          If you try this yourself

          • Point the agent at the custom chat UI guide and start on the demo Site ID, so it can hold real conversations from the first hour.
          • Probe the prompt before building the UI. Here, a first run showed the Stand-in wrongly denying an app’s trigger it couldn’t see, so app-card questions now carry the app’s triggers and actions.
          • Keep the vocabulary closed and forgiving: the Stand-in sometimes writes [[Pipewell]] without “App:”, or -> for an arrow. Normalize, look up, and fall back to plain text.
          • Drive the renderer with fake states, too. Handoffs, follow-up offers and link cards never happen on the demo site, but a test can feed them in through useClient().
