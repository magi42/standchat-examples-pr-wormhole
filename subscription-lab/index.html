    SMALL PRINT, BIG CLARITY
    The rules of this little world.
    A bounded model for asking better questions. Meterwick is an invented demo, not a payment processor.
    Two plans. One seat price.
    Launch: $90/month. Scale: $180/month. Every seat: $10/month. We start with 3 seats; each seat event adds 2.
    A deliberately simple month.
    September has 30 days. Changes apply at the start of the selected day. Same-day events run in the order added. Up to 12 events.
    Credits are just as visible.
    Each adjustment is the monthly rate change × remaining days ÷ 30. Fractional cents carry forward; we round the running subtotal and show the difference on each line.
    Service and collection are separate.
    Pause stops all charges and keeps your plan and seats. Resume restores them. Cancel ends service permanently. A failed payment changes only collection status.
    Changes can wait.
    Upgrades and extra seats while paused take effect on resume. Repeated upgrades, pauses, or resumes can have no effect. Service changes after cancellation are ignored.
    Only what you see.
    No tax, discounts, automatic retries, or next-month calculations. Edits stay in this tab; no real accounts, invoices, or payments are created.
    

    
    How it works
    A local billing model. A real conversation.
    The timeline and invoice run entirely in your browser. Stand Chat answers inside the page with the exact scenario the visitor is asking about.
    Try it
    1. Choose a story, or add up to 12 events. Drag a change onto a date; on touch or keyboard, use the date selector and its + button.
    2. Select an invoice line or timeline event to inspect the calculation. Use Undo, remove an event, or Reset to the starting subscription.
    3. Choose “Ask about this adjustment,” review the context, and send a question. Only sending starts a conversation. Reloading recovers that conversation when session storage is available.
    Send the whole scenario through supported text messages
    billing.js is a pure, integer-based model. The local copy of stand-inline.js adds a prepareMessage callback so every new message includes a fresh snapshot. Retries retain their original payload and message ID. Responses are rendered safely as text and never interpreted as page commands.
    import { contextualMessage } from './billing.js';
import './stand-inline.js';

const chat = document.querySelector('#billing-chat');
chat.prepareMessage = question =>
  contextualMessage(question, events, selected);
// This only prepares context. Send is an explicit visitor action.
    The copied visitor client performs responder discovery, creates a session with initialMessage, sends subsequent text through /v1/sessions/:id/messages, and receives canonical replies over a WebSocket. It preserves AI/human identity, notices, attribution, handoffs, email follow-up offers, pending sends, and bounded recovery. An uncertain start requires an explicit visitor decision.
    Copy this example
    npx degit standchat/examples/subscription-lab my-billing-lab
    Serve the copied folder with any static HTTP server. No installation or build is needed. Keep index.html, style.css, app.js, billing.js, stand-inline.js, and stand-visitor.js together. The /_shared/ files provide optional gallery chrome; the demo works without them.
    <script defer src="https://cdn.stand.chat/widget/stand.js"
  data-stand-id="YOUR-SITE-ID" data-stand-hide-button="true"></script>
<stand-inline id="billing-chat" site="YOUR-SITE-ID"
  scope="meterwick-billing" look="card" grow="unfold">
</stand-inline>
    Replace both demo Site IDs using your installation snippet from Sites in Stand. The shared demo answers with a Stand-in and doesn’t appear in your account. Configure your own team, knowledge, and instructions for production; the UI does not supply a billing backend. Read the official custom chat UI contract for the beta API and plan requirements.
